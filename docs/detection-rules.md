# Threat Detection Rules & Heuristic Methodology

The threat detection engine uses deterministic, evidence-based heuristics to identify suspicious network behavior, reconnaissance, and protocol anomalies.

> **Defensive Philosophy**: The analyzer reports observable telemetry anomalies and patterns. It does not falsely claim proof of malware or compromise without external threat intelligence corroboration.

## Detailed Rule Specifications

### RULE 001: Potential TCP SYN Scanning Pattern

- **Category**: Reconnaissance
- **Purpose**: Detect active port scanning tools (such as Nmap SYN stealth scans `-sS`, Masscan, or ZMap) scanning target endpoints.
- **Evaluation Logic**:
  1. Filters TCP packets having `SYN = 1` and `ACK = 0`.
  2. Aggregates SYN transmission counts per source IP address.
  3. Evaluates unique destination ports targeted (vertical scan) and unique destination IPs targeted (horizontal scan/network sweep).
  4. Correlates against conversation flows to count completed 3-way handshakes (`SYN` -> `SYN-ACK` -> `ACK`).
  5. Triggers when SYN volume $\ge 25$ packets, unique ports $\ge 20$ (or unique hosts $\ge 15$), and handshake completion ratio $\le 15\%$.
- **Generated Evidence**:
  - `syn_packets_transmitted`: Total SYN packets sent by the source host.
  - `unique_destination_ports_targeted`: Count of unique destination ports probed.
  - `unique_destination_hosts_targeted`: Count of unique destination IP addresses probed.
  - `completed_handshakes`: Established connections formed.
  - `handshake_completion_ratio`: Percentage of attempts that reached established status.
  - `sample_targeted_ports`: First 10 ports probed.

### RULE 002: Potential Connection Flood

- **Category**: Traffic Anomaly
- **Purpose**: Identify extreme packet transmission spikes from a single endpoint that may indicate DoS, connection exhaustion, or aggressive automated tooling.
- **Evaluation Logic**:
  1. Computes total packets and transmission rate ($R = \frac{\text{packets}}{\text{duration}}$) for each source IP.
  2. Flags sources generating $\ge 80.0$ packets/second or accounting for $\ge 70\%$ of the total capture volume.
- **Generated Evidence**:
  - `packet_count`: Total packets from the endpoint.
  - `packet_rate_per_second`: Average transmission rate across capture duration.
  - `ratio_of_total_capture`: Proportion of overall capture traffic generated by this host.

---

### RULE 003: Unusual Destination Port Activity

- **Category**: Security Observation
- **Purpose**: Highlight communications directed toward ports known to host default C2 frameworks, Trojans, or unauthorized remote shells.
- **Monitored Ports**:
  - `1337` (Elite backdoor)
  - `2323` (Alternative Telnet / Mirai botnet)
  - `4444`, `4445` (Metasploit default and secondary listener ports)
  - `5555` (ADB remote Trojan / Android debugging)
  - `6667` (IRC C2)
  - `8888`, `9999` (Alternative HTTP / Trojan)
  - `31337` (Back Orifice)
- **Generated Evidence**:
  - `destination_port`: Targeted port number.
  - `service_reference`: Known service or threat framework reference name.
  - `packet_count` & `total_bytes`: Volume transmitted on the unusual port.
  - `source_hosts` & `destination_hosts`: Participating endpoints.

---

### RULE 004: DNS Query Volume Anomaly

- **Category**: DNS Anomaly
- **Purpose**: Detect anomalous spikes in DNS resolution traffic originating from client hosts.
- **Evaluation Logic**:
  1. Tracks DNS queries by client IP.
  2. Flags hosts issuing $\ge 100$ total queries or querying at $\ge 20$ queries/second.
- **Generated Evidence**:
  - `total_dns_queries`: Overall DNS queries from the source.
  - `queries_per_second`: Rate of DNS requests.
  - `unique_domains_queried`: Count of distinct domain names requested.

---

### RULE 005: Suspicious DNS Characteristics (Tunneling / DGA)

- **Category**: DNS Anomaly
- **Purpose**: Detect DNS data exfiltration, covert tunneling tools (e.g. `dnscat2`, `iodine`), and Domain Generation Algorithms (DGAs).
- **Evaluation Logic**:
  1. Computes the Shannon entropy ($H$) of the leftmost subdomain label:
     $$H = -\sum_{i=1}^{n} P(x_i) \log_2 P(x_i)$$
  2. Evaluates total query length in characters.
  3. Triggers when query length $\ge 50$ characters, or when a subdomain label $\ge 12$ characters exhibits Shannon entropy $\ge 3.85$ bits/symbol.
- **Generated Evidence**:
  - `suspicious_query_count`: Total abnormal queries detected.
  - `sample_queries`: List containing domain name, length, and computed Shannon entropy score.

---

### RULE 006: Repeated Failed TCP Connections

- **Category**: Connection Anomaly
- **Purpose**: Identify endpoints making repeated connection attempts to closed or filtered ports resulting in TCP RST packets or timeouts.
- **Evaluation Logic**:
  1. Analyzes flows where `syn_count > 0` but `completed_handshake == False`.
  2. Triggers when an endpoint has $\ge 25$ unestablished flow attempts.
- **Generated Evidence**:
  - `failed_connection_count`: Number of unestablished connection attempts.
  - `unique_failed_targets`: Number of distinct IP:Port endpoints that failed.

---

### RULE 007: ICMP Volume Anomaly

- **Category**: Traffic Anomaly
- **Purpose**: Detect network ping sweeps, ICMP floods, or path MTU discovery issues.
- **Evaluation Logic**:
  1. Tallies ICMP Echo Requests, Echo Replies, and Destination Unreachable messages.
  2. Triggers when a host transmits $\ge 80$ ICMP packets or exceeds $15$ ICMP packets/second.
- **Generated Evidence**:
  - `icmp_packet_count`: Total ICMP packets sent.
  - `icmp_packets_per_sec`: Average transmission rate.

---

### RULE 008: Cleartext Protocol Observation

- **Category**: Cleartext Communication
- **Purpose**: Identify unencrypted network protocols (HTTP, FTP, Telnet, POP3, IMAP) that transmit credentials, session tokens, or sensitive payload data in cleartext.
- **Evaluation Logic**:
  1. Inspects application layer protocol type and well-known unencrypted service ports (80, 21, 23, 110, 143).
  2. Extracts targeted hostnames, URIs, and active endpoint pairs.
- **Generated Evidence**:
  - `protocol`: Name of the unencrypted protocol.
  - `packet_count`: Total cleartext packets observed.
  - `observed_hosts`: Extracted HTTP hostnames or endpoints.
